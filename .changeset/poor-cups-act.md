Make generated event gates prove the bytes their parse helpers skip

`parse<Event>` and `parse<Program>Event` decode an event's body from an offset past its hidden prefix, which is only sound when the check in front of them has already proven at least that many bytes. The check was built from `discriminators` while the offset was the full width of the prefix, so an IDL that declares fewer discriminators than the prefix carries produced a check proving less than the offset consumes. An event with a `[const8, const8]` prefix and a single discriminator on the first entry rendered an `is<Event>` proving 8 bytes in front of `decode(data, 16)`, and any buffer of length 8–15 carrying that discriminator made `is<Event>` return `true` and `parse<Event>` throw `SolanaError: SOLANA_ERROR__CODECS__INVALID_BYTE_LENGTH` instead of returning `null`. Anchor-extracted IDLs declare every prefix entry, so no existing fixture reached it.

The decode offset and the byte count it consumes are now produced together as one value, and the offset is reconciled against the check at generation time: when the discriminators already prove the full width the output is unchanged, and when they fall short the gate gains a `data.length >= N` clause covering the remainder. The gate therefore proves every byte its offset skips, and the short buffer is rejected as a mismatch rather than throwing. The clause covers the prefix, not the body behind it — an event that matches but carries a truncated body still throws on decode, which is the contract its docblock has always stated. The aggregate arms in `identify<Program>Event` gain the same clause, since that function owns every byte comparison the arms' offsets depend on.

Several narrower defects fall out of the same reconciliation, each one an offset derived from something other than the bytes the generated code actually skips.

The offset now always comes from the hidden prefix. The CPI-framed path took it from the framing constant plus the declared discriminators instead, so a framed event carrying a prefix entry no discriminator was declared for decoded its body from inside that entry — well-typed wrong values, no error. Nested `hiddenPrefixTypeNode`s were summed one level deep, with the same result, even though the decoder is built from the innermost type and skips none of them; every level is now counted, and an event whose data reaches that inner type through any other wrapper — a size prefix, an offset, a sentinel — drops its parse helpers, because such a wrapper can contribute leading bytes the offset has no way to count. A single-entry prefix took its offset from the first discriminator constant rather than the entry's own width, which decoded from the wrong position whenever the entry was the wider of the two.

Byte counts now come from the value each constant renders as, not from its declared type. A constant is emitted holding its raw value while its encoder pads to the declared size, so `<EVENT>_DISCRIMINATOR.length` is the value's width and not the wire's: naming it in the offset understated a short constant, and crediting the declared width to the `containsBytes` check in front of it dropped a length clause the offset needed. The named form is kept only where the two widths agree, which is every discriminator Anchor emits, and a literal is used everywhere else. Widths that are not byte constants come from the same byte-size visitor the account and type pages size themselves with, so an entry is measured once across the generator; an entry with no fixed width drops the event's parse helpers with a warning rather than emitting an offset the gate cannot cover.

This is a minor rather than a patch bump because those cases change what is emitted for an IDL that reaches them. An event with an unbounded prefix entry loses its `is<Event>` and `parse<Event>` exports and its variant in the program's event unions, so a call site that referenced them stops compiling; the events whose offsets were wrong now decode from a different position than before. The previous output was wrong in every one of those cases, but the changes are not source-compatible. IDLs extracted from Anchor are unaffected — `nodes-from-anchor` builds each prefix entry and its discriminator in the same expression, at the declared width, so the two quantities always agree there — and every existing e2e fixture regenerates byte-identical.
